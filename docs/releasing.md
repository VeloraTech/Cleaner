# Creating a release

Cleaner releases are driven by stable semantic-version Git tags. The tag must
match `package.json` exactly: `v0.1.5` releases package version `0.1.5`. A mismatch
fails before dependencies are installed or publication can occur.

## One-time setup

### GitHub Actions

The workflow is `.github/workflows/release.yml`. Ensure GitHub Actions are
enabled for the `VeloraTech/Cleaner` repository and that repository policy
allows the workflow's `GITHUB_TOKEN` to create releases. The workflow requests
`contents: write` for release creation and `id-token: write` for npm OIDC.

No npm token or GitHub secret is required for publishing.

### npm trusted publisher

In npmjs.com, open `@coachlogic/cleaner` package settings and add a GitHub Actions
trusted publisher with these exact values:

- Organization/user: `VeloraTech`
- Repository: `Cleaner`
- Workflow filename: `release.yml`
- Environment: leave unset; this workflow does not use a GitHub environment
- Allowed publishing action: permit direct `npm publish`

The package's `repository.url` must remain aligned with
`https://github.com/VeloraTech/Cleaner.git`. Do not add an npm token to the
repository. npm's trusted publisher exchanges GitHub's short-lived OIDC identity
for publish permission. This workflow uses Node.js 24 and npm 11.5.1 or newer,
which are required by the current npm trusted-publishing implementation.

Cleaner itself supports Node.js `>=18`; Node 24 is the release runner version
needed for OIDC publishing.

## Prepare a version

First select the next package version. For a patch release:

```bash
npm version patch --no-git-tag-version
```

This updates both `package.json` and `package-lock.json`. Run the local release
check, commit the version and release-note changes, and push the commit before
tagging:

```bash
npm run release:check
git add package.json package-lock.json CHANGELOG.md README.md docs/releasing.md docs/cli.md .github/workflows/release.yml scripts/release-check.mjs
git commit -m "chore: prepare release"
git push origin HEAD
```

`release:check` runs tests, builds Cleaner, checks tag/package metadata, and
validates the npm dry-run package contents. To also check an explicit tag:

```bash
npm run release:check -- --tag v0.1.5
```

The tag must match the version in `package.json`.

## Create the release

From the commit containing the version change, create and push the matching tag:

```bash
git tag v0.1.5
git push origin v0.1.5
```

For later releases, use the version in `package.json`. The
workflow will:

1. Validate the tag/version match.
2. Install locked dependencies with `npm ci`.
3. Run tests and build the package.
4. Inspect `npm pack --dry-run` contents and verify package metadata and CLI files.
5. Create the `.tgz`, using the filename reported by npm itself.
6. Calculate `SHA256SUMS` from that exact tarball.
7. Create or update the GitHub Release named `Cleaner vX.Y.Z`, attaching the
   tarball and checksum. Retries update the existing release and replace the
   same-named assets rather than creating a duplicate.
8. Publish `@coachlogic/cleaner` through npm trusted publishing/OIDC.

A failed validation, install, test, build, or package check stops the job before
GitHub Release creation and npm publication. npm publishing happens after the
GitHub Release step; if publishing fails, correct the trusted-publisher setup and
retry the same tag.

The package currently includes `dist/src`, `README.md`, `LICENSE`,
`CHANGELOG.md`, and npm's generated `package.json`. Tests, fixtures, scripts,
source files, and local artifacts are not included. TypeScript source maps remain
included because the project currently enables them in `tsconfig.json`.

## Test a package locally

Run the local release check first, then create and inspect a tarball:

```bash
npm run release:check
npm pack --dry-run
npm pack
```

The filename is generated by npm from the package name and version, for example
`coachlogic-cleaner-0.1.5.tgz`. Test it in another project without publishing:

```bash
npm install /path/to/coachlogic-cleaner-0.1.5.tgz
npx cleaner . --diff
```

On Windows, use the full path to the `.tgz` file. Do not run `npm publish` from
a developer workstation; tagged GitHub Actions releases handle publication.

## Troubleshooting npm publish

If the GitHub Release and assets exist but `npm publish` returns `E404`, the
package may exist while npm is rejecting the workflow's publish identity. Check
the trusted publisher on the `@coachlogic/cleaner` npm package settings:

- GitHub owner: `VeloraTech`
- Repository: `Cleaner`
- Workflow filename: `release.yml` (filename only, case-sensitive)
- Environment: unset, unless the workflow is changed to use one
- Allowed action: direct `npm publish`

Also confirm the GitHub Actions run uses a GitHub-hosted runner and has
`id-token: write`. Do not add an npm token to the repository. Once the npm
trusted-publisher configuration is corrected, rerun the failed workflow for the
same tag. The existing GitHub Release is updated idempotently and the publish
step is retried; do not create a new version unless the package was actually
published.
